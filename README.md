# AI Candidate Scoring System

Веб-сервис сравнения резюме с требованиями вакансии: загрузка PDF/TXT, навыки и опыт, Score 0—100, объяснение результата и история решений HR.

## Запуск

Нужны Git и Docker с Compose. Для стенда ПМИ: x86-64 Linux/Windows, минимум 2 ядра, 8 ГБ RAM, 100 ГБ диска, без GPU.

```bash
docker compose up --build -d --wait
```

- Интерфейс: `http://localhost:3000`
- API и Swagger: `http://localhost:8000/docs`
- Конфигурация, версии и хэши: `GET /config`
- Состояние API: `GET /status`; БД: `GET /health`

Работают **четыре отдельных контейнера**: React/Nginx, FastAPI, скорер и MongoDB. Образы не содержат реальные PDF/JSON. Данные можно создать синтетическим генератором либо загрузить из файлов. Импорт внешних JSON по умолчанию отключён; его локальное включение требует `ENABLE_EXTERNAL_IMPORTS=true` и, для кнопок UI, `REACT_APP_ENABLE_EXTERNAL_IMPORTS=true` при сборке.

Настройки задаются окружением; примеры — `.env.example`. Полные инструкции запуска, обновления и восстановления: [RUNBOOK](docs/RUNBOOK.md). Локальная разработка проверена на Python 3.13 и Node.js 22; точные Python-зависимости — `requirements.lock`, фронтенда — `frontend/package-lock.json`.

## Алгоритм

```text
Score = round(100 × (0.85 × покрытие навыков + 0.15 × TF-IDF cosine))
```

Критический навык весит 2, обычный — 1. Словарь вариантов написания расширяется через `config/skills.json`, без изменения Python. TF-IDF обучается на фиксированном референс-корпусе; Score одной пары одинаков в пулах 10 и 200. Опыт используется для сортировки равных оценок. Контактные и демографические поля исключаются из обоих компонентов Score. При пустом тексте/отсутствии совпавших требований оценка равна 0.

Веса, версия и пути к справочнику находятся в `config/algorithm.json`. Каждый сохранённый результат содержит fingerprint алгоритма и дату. [Подробная архитектура](docs/ARCHITECTURE.md).

## Работа с интерфейсом

Создайте вакансию через форму или файл, загрузите резюме, выберите вакансию и критические навыки, нажмите «Рассчитать скоринг». В карточке видны найденные/отсутствующие навыки, критические пробелы, вклад компонентов и исходный текст с подсветкой. Решения «Да»/«Нет» сохраняются с датой и историей. Результаты можно выгрузить в JSON. [Руководство пользователя](docs/USER_GUIDE.md).

Оригинал загруженного файла хранится без преобразований вместе с SHA-256; при удалении документа удаляются связанные результаты и история HR. Ограничения: PDF/TXT, 8 МиБ, 200 страниц PDF, миллион символов текста; OCR отсутствует.

## Прогон куратора

`python scripts/benchmark_real_data.py` — первые 10 вакансий JSON-набора, все 194 резюме, готовые размеченные навыки, порог 0.1. Результаты — `reports/curator_benchmark/`. Для диагностики автоматического извлечения укажите `--ranking-inputs extracted`. [Согласованная версия и измерения от 27.10.2026](reports/curator_pmi_2026-10-27/README.md).

В текущей версии сохранены группы навыков куратора и фиксированный TF-IDF для независимости Score от пула.

## Испытания

```bash
python -m pip install -r requirements.lock -r tests/requirements.txt
python -m pytest -q
python -m pmi run --live
```

Последняя команда выполняет проверки ПМИ в отдельном Docker-проекте на портах 18000/13000, не очищая рабочую БД. Порядок, фиксация входов, все примеры А-1—А-20 и границы автоматизации: [методика испытаний](docs/PMI.md). Для интерфейса: `CI=true npm test --prefix frontend -- --watchAll=false --runInBand` и `npm run build --prefix frontend`.

Приёмочный набор: 10 вакансий, 200 синтетических PDF-резюме по пяти направлениям, 2000 размеченных пар. Данные и параметры фиксируются до испытаний. Порог релевантности — 0.1; критерии качества берутся из ПМИ. [Протокол](reports/pmi/protocol.md), [качество](reports/pmi/quality.md), [ручной лист комиссии](docs/PMI_MANUAL.md). Выполнение автоматических тестов не заменяет независимую проверку Заказчиком и оформление акта.

Реалистичный генератор шести ИТ-профилей и реальные PDF/JSON проверяются отдельными `scripts/benchmark_*.py`. Для реальных пар используется только диагностическое покрытие размеченных навыков: экспертной разметки релевантности нет. Исторические отчёты не относятся автоматически к новой версии.

## Структура

- `api/` — HTTP, файлы и журнал; `db/` — MongoDB.
- `scorer/` — навыки, TF-IDF, ранжирование и внутренний HTTP-сервис.
- `frontend/` — React; `Parser/` — отдельный сборщик данных.
- `config/` — алгоритм и расширяемый справочник.
- `pmi/`, `tests/pmi/` — воспроизводимые приёмочные сценарии.
- `data/pmi/` — зафиксированный синтетический набор; исходные пользовательские PDF не добавляются в Git.
- `scripts/` — диагностика; `reports/` — отчёты; `docs/` — документация.

Для штатной остановки — `docker compose stop`; для восстановления — `docker compose up -d --wait`. Именованные тома сохраняют данные.
