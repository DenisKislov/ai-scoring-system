# Данные и методика оценки

В проекте используются реальный текстовый корпус куратора и отдельный воспроизводимый синтетический набор. Ни один набор не содержит независимой экспертной оценки релевантности всех пар «вакансия — резюме».

## Реальный корпус

| Источник | Назначение |
|---|---|
| `superjob_dataset.json` | 111 вакансий: структурированные выдержки или `raw_text`, размеченные `expected_skills` |
| `dataset_resume.json` | 194 резюме в аналогичном формате |
| `ground_truth_resumes.csv` | Каноническая разметка: 194 документа, 896 колонок навыков |
| `ground_truth_vacancies.csv` | Каноническая разметка: 51 документ, 1262 колонки навыков |
| `resumes/`, `vacancies/` | Исходные PDF; числовое имя файла соответствует `id` в CSV |
| `source/ground_truth_resumes_assembled.csv` | Дополнительная исходная версия разметки куратора; отличается от канонической, автоматически не подменяет её |
| `Resume_table_2_normalized.csv`, `Vacancies_table_2_normalized.csv` | Сохранённые таблицы предыдущего состояния проекта; не источник разметки новых бенчмарков |

JSON, CSV и PDF имеют разные составы и схемы. PDF без соответствующей однозначной строки канонического CSV исключаются из оценки PDF. `expected_skills` в JSON и колонки CSV — разметка навыков документа, а не оценка пригодности человека к работе. Неполная разметка может считать правильные дополнительные находки ложноположительными.

Проверка JSON:

```bash
python scripts/benchmark_real_data.py --limit 0
python scripts/benchmark_real_data.py --limit 0 --threshold 0.1 --output-prefix real_data_pmi_threshold
python scripts/benchmark_real_data.py --limit 0 --ranking-inputs annotated --output-prefix real_data_oracle
```

По умолчанию `extracted` передаёт скореру только тексты. Отдельный режим `annotated` передаёт ему эталонные навыки и добавляет навыки вакансии в её текст: это oracle-диагностика матчинга, а не проверка извлечения или полного пользовательского сценария. Извлечение P/R/F1 в обоих режимах считается отдельно, по каждому тексту, с разбивкой на структурированные выдержки и полные PDF-тексты.

Проверка загрузки PDF и ранжирования:

```bash
python scripts/benchmark_pdf_corpus.py --threshold 0.1
```

В обоих реальных бенчмарках graded proxy-релевантность равна доле размеченных навыков вакансии, присутствующих среди размеченных навыков резюме. Бинарный порог выбирается явно; по умолчанию JSON использует 0.3, PDF — 0.5. `--threshold 0.1` позволяет сопоставлять результат с порогом ПМИ. Сам выбор порога не означает полную приёмку: остаются ограничения разметки, состава корпуса и объёма проверок. Отчёты указывают точные настройки и число запросов, участвовавших в усреднении.

## Пополнение JSON из PDF

Историческое имя скрипта сохранено, но он использует канонические пути `data/ground_truth_*.csv` и `data/{resumes,vacancies}/`:

```bash
python scripts/extend_datasets_from_assembled.py --dry-run
python scripts/extend_datasets_from_assembled.py
```

Скрипт добавляет только недостающие ID, берёт последнюю запись при дубликатах JSON и сохраняет существующие тексты и метки. Он не синхронизирует новую разметку с уже имеющимися JSON-записями. Конфликтующие дубликаты ID в CSV вызывают ошибку. Для другого источника пути выбираются явно, например:

```bash
python scripts/extend_datasets_from_assembled.py --resume-csv data/source/ground_truth_resumes_assembled.csv --resume-pdf data/resumes --dry-run
```

Доступны также `--vacancy-csv`, `--vacancy-pdf`, `--resume-json`, `--vacancy-json`. Канонические CSV автоматически не перезаписываются.

## Синтетический набор

`synthetic_roles.json` задаёт компактные стеки шести направлений: Python, Data Science, Frontend, DevOps, QA и Data Engineering. Большой `skills_by_profession.json` сохранён как источник онтологии; генератор не превращает его целиком в требования вакансии.

`profiles.py` меняет структуру и формулировки текстов, использует сокращения технологий и согласованную карьерную хронологию. `synthetic.py` выбирает 6–9 обязательных навыков вакансии, два критических, отдельные желательные навыки и требуемый стаж. Пул содержит кандидатов своей, смежных и других профессий. Часть известных кандидату навыков скрыта в тексте; отдельно могут упоминаться технологии, знакомые только по курсам.

Истинная синтетическая релевантность рассчитывается до написания текста:

`0.55 × покрытие обязательных навыков + 0.20 × покрытие критических + 0.15 × соответствие роли + 0.10 × соответствие опыта`.

Эта формула и распределение генератора сохранены при интеграции куратора. Бенчмарк получает только тексты; `db.seed` и API сохраняют навыки, извлечённые рабочим `scorer.extract_skills`, не скрытое множество способностей.

```bash
python scripts/benchmark_synthetic.py
python tests/eval_synthetic.py
```

Основной прогон: seeds 42/7/99, 12 вакансий на seed, по 30 кандидатов, бинарная релевантность ≥ 0.65. Считаются Precision@K, Recall@K, MAP, MRR, NDCG@K и Spearman. Параметр `--threshold` открыт для явных дополнительных экспериментов, но синтетическая релевантность имеет другой смысл, чем proxy реального корпуса. Ориентир NDCG@10 ≥ 0.80 в `eval_synthetic.py` — историческая регрессионная проверка, а не полный критерий текущего ПМИ.

## Отчёты и история

Текущие результаты записываются в `reports/` с датой, версией протокола, выбранным порогом и методом формирования релевантности. Прежние результаты перенесены без пересчёта в `reports/history/pre_curator/`; они относятся к старому scorer и корпусу. `DATA_ENGINEER.md` сохранён как исторический документ о первой версии генератора.

## Приёмочный набор ПМИ

`data/pmi/` содержит 200 синтетических PDF-резюме, по 40 в пяти профессиональных направлениях, и 10 вакансий. `dataset.json` хранит разметку всех 2000 пар, а `manifest.json` — хэши данных, кода и конфигурации. Генерация и испытания: `python -m pmi build`, `python -m pmi run --live`; подробности в `docs/PMI.md`. Это отдельный контролируемый набор; прежняя более шумная синтетика и внешние документы остаются диагностическими.

Внешние `superjob_dataset.json` и `dataset_resume.json` являются локальными входами, исключены из Git и Docker-образа. Для демонстрации ПМИ используются только синтетические данные.
