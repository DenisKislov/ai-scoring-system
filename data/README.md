# data/ — синтетические данные с ground-truth relevance

Заказчик реальные резюме дать не может (152-ФЗ), лейблов тоже нет — поэтому обучающе-оценочный датасет генерируется здесь. Метод: **контролируемое внедрение навыков** — для вакансии создаются резюме с заданной долей совпадения `overlap`, которая и становится graded ground-truth relevance (что кандидат *знает*), а в текст навыки попадают с реалистичным шумом. Скорер должен восстановить истинный ранг из зашумлённого наблюдения.

## Файлы

| Файл | Роль |
|---|---|
| [`skills_by_profession.json`](skills_by_profession.json) | Единственный источник правды: навыки и субъектные фразы по профессиям |
| [`profiles.py`](profiles.py) | Загрузка профессий + рендер русских текстов вакансий/резюме |
| [`synthetic.py`](synthetic.py) | Генерация датасета с разметкой (контролируемое внедрение навыков) |

## skills_by_profession.json

4 профессии, у каждой три поля:

| Профессия | Навыков | Поля |
|---|---|---|
| Python-разработчик | 95 | `skills`, `vacancy_subjects`, `resume_subjects` |
| Data Scientist | 67 | то же |
| Frontend-разработчик | 141 | то же |
| DevOps-инженер | 69 | то же |

`skills` — канонические навыки специалиста (все распознаются онтологией скорера); `vacancy_subjects`/`resume_subjects` — доменные фразы для реалистичного русского текста. Можно свободно расширять. Чистится/валидируется утилитой `tools/clean_profession_skills.py`.

## profiles.py

`ROLES` (из JSON) + `ROLE_KEYS`. `render_vacancy` / `render_resume` собирают реалистичный русский текст; в частности `render_resume` пишет `"Опыт работы: N лет."` (1–10) — откуда `db.builders.experience_years` берёт годы для тайм-брейка.

## synthetic.py

- `generate_dataset(n_vacancies, n_resumes, seed)` — `n_vacancies` вакансий, у каждой `n_resumes` размеченных резюме; `overlap` равномерно по `[0,1]`, пул затем перемешивается.
- `generate_resume(vacancy, overlap)` — при `overlap ≥ 0.5` кандидат **той же** профессии (sample доли навыков вакансии); иначе **чужой** профессии. `true_relevance` = реальная доля совпадения навыков.
- `_noisy_skills` — текст несёт лишь зашумлённое подмножество: ~10–35% известных навыков пропускается + 1–3 навыка из чужой профессии. Это намеренно рвёт связь `keyword_score == true_relevance`, так что метрика измеряет восстановление ранга, а не «код запустился».

Используется из `db.seed` (заливка в Mongo), `tests/eval_synthetic.py` (метрики), `tools/build_reference_corpus.py` (корпус для TF-IDF). Самостоятельного CLI нет.
