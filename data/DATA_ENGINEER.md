# Отчёт Data Engineer: Генерация синтетических данных для системы скоринга кандидатов

##  Роль

**Роль в проекте:** Data Engineer

**Ответственность:** Разработка и настройка генератора синтетических данных для обучения и тестирования системы скоринга кандидатов. Создание реалистичного датасета с ground-truth разметкой для валидации алгоритма ранжирования.


## Основные задачи

1. **Настроить генератор синтетических данных** — использовать библиотеку Faker и шаблоны профессий для создания реалистичных резюме и вакансий.

2. **Использовать базу навыков 4 профессий** — применить файл `skills_by_profession.json` с онтологией навыков для Python-разработчика, Data Scientist, Frontend-разработчика и DevOps-инженера.

3. **Реализовать контролируемое внедрение навыков** — генерировать резюме с заданным процентом соответствия (overlap 0-100%) к целевой вакансии, что создаёт ground-truth разметку для валидации алгоритма.

4. **Добавить реалистичный шум в тексты резюме** — симулировать реальные условия, где кандидаты не всегда указывают все навыки и добавляют нерелевантную информацию.

5. **Сгенерировать датасет с ground-truth разметкой** — создать набор данных, где для каждого резюме известен правильный процент соответствия вакансии, что позволяет объективно оценить качество алгоритма скоринга.

## Как создавались коллекции hh и hh_resumes

### Архитектура генерации данных
Генератор работает в два этапа:
#### Этап 1: Создание вакансий (коллекция hh)
Команда:
```bash
python -m db.seed --vacancies 10 --resumes 40 --seed 42
```

##### Процесс:
- Скрипт db/seed.py загружает онтологию навыков из data/skills_by_profession.json
- Для каждой вакансии случайным образом выбирается профессия (циклически: Python-разработчик → Data Scientist → Frontend → DevOps)
- Из базы навыков профессии выбирается набор ключевых навыков (skills)
- Генерируется текст вакансии с использованием шаблонов из data/profiles.py
- Вакансия сохраняется в MongoDB в коллекцию hh

##### Структура документа вакансии:
```json
{
  "_id": ObjectId("6a707c8c301dfa2a89f01d7f"),
  "url": "https://hh.ru/vacancy/syn_0_Python-разработчик",
  "title": "Python-разработчик",
  "description": "Вакансия: Python-разработчик. Требуемый опыт работы: от 1 лет. Мы ищем...",
  "skills": ["Python", "Django", "PostgreSQL", "Git", "Docker", ...],
  "author_name": "Synthetic Corp",
  "tags": [],
  "_synthetic": true
}
```

#### Этап 2: Создание резюме (коллекция hh_resumes)
##### Процесс для каждого резюме:
- Определяется целевая вакансия (для которой генерируется резюме)
- Задаётся целевой процент соответствия (_true_relevance) — случайное число от 0 до 1
- Из навыков целевой вакансии выбирается процент, соответствующий _true_relevance (например, при 0.874 берётся 87.4% навыков)
- Добавляются случайные навыки из других профессий (шум)
- Генерируется текст резюме с использованием Faker (ru_RU) — имя, опыт работы, описание
- Часть навыков намеренно пропускается в тексте (симуляция неполного резюме)
- Резюме сохраняется в MongoDB в коллекцию hh_resumes

##### Структура документа резюме:
```json
{
  "_id": ObjectId("6a707c8d301dfa2a89f01d95"),
  "url": "https://hh.ru/resume/syn_0_21",
  "title": "Data Scientist",
  "specialization": "Data Scientist",
  "experience": "Татьяна Кузьминична Соболева, позиция: Data Scientist. Опыт работы: 3 ...",
  "skills": ["Python", "Machine Learning", "Pandas", "SQL", ...],
  "tags": [],
  "_synthetic": true,
  "_target_vacancy_url": "https://hh.ru/vacancy/syn_0_Python-разработчик",
  "_true_relevance": 0.2
}
```
##### Ключевые поля:
- _synthetic: true — маркер синтетического происхождения
- _target_vacancy_url — ссылка на целевую вакансию (для какой вакансии создавалось резюме)
- _true_relevance — ground-truth разметка (известный процент соответствия)

## Шум в текстах резюме
### Зачем нужен шум?
В реальных резюме кандидаты:
- Не всегда указывают все свои навыки
- Добавляют нерелевантную информацию
- Используют разные формулировки
- Допускают ошибки и опечатки
Чтобы алгоритм скоринга работал в реальных условиях, синтетические данные должны имитировать эти особенности.

### Типы шума, реализованные в генераторе
1. Пропуск навыков (Skill Dropout)
Механизм: Даже если навык есть в списке skills резюме, он может не попасть в текст описания.
Пример:
```json
{
  "skills": ["Python", "Django", "PostgreSQL", "Git"],
  "experience": "Разработка веб-приложений на Django. Работа с базами данных..."
  // Python и Git не упомянуты в тексте, хотя есть в skills
}
```
Процент пропуска: ~10-35% навыков не попадают в текст (случайный процент для каждого резюме)

Реализация в коде (synthetic.py):
```python
def _noisy_skills(skills, vacancy, profession, rng):
    out = list(skills)
    if len(out) > 2:
        # Случайный процент пропуска для каждого резюме
        drop = round(len(out) * rng.uniform(0.10, 0.35))
        for idx in sorted(rng.sample(range(len(out)), drop), reverse=True):
            out.pop(idx)
    # ...
```

2. Добавление нерелевантных навыков (Noise Skills)
Механизм: В резюме добавляются навыки из других профессий, которые не требуются для целевой вакансии.

Пример для вакансии Python-разработчик:
```json
{
  "skills": ["Python", "Django", "PostgreSQL", "Git", "Docker",
             "C++", "Kubernetes", "React", "Java"]  // последние 4 — шум
}
```

Процент шума: ~1-3 нерелевантных навыка добавляются к каждому резюме
Реализация в коде:
```python
others = [k for k in ROLE_KEYS if k not in (profession, vacancy["role"])]
if others:
    for _ in range(rng.randint(1, 3)):
        out.append(rng.choice(ROLES[rng.choice(others)]["skills"]))
```

3. Вариативность формулировок

## ground-truth разметка

Ground-truth — это "правильный ответ", который известен заранее. В нашем случае это поле _true_relevance — известный процент соответствия резюме вакансии.

Как создаётся ground-truth
Процесс:
- Для каждого резюме задаётся целевой процент соответствия (overlap) — случайное число от 0 до 1
- Из навыков целевой вакансии выбирается ровно этот процент навыков
- Этот процент записывается в поле _true_relevance

Пример:
```json
{
  "_true_relevance": 0.874,  // 87.4% навыков вакансии есть в резюме
  "skills": ["Python", "Django", "PostgreSQL", ...]  // 87 из 100 навыков
}
```

Зачем нужен ground-truth?
- Валидация алгоритма — можно объективно оценить, насколько хорошо алгоритм ранжирует кандидатов
- Расчёт метрик — nDCG, Spearman, Precision@K требуют известных правильных ответов
- Сравнение подходов — можно сравнить разные алгоритмы скоринга на одном датасете

Проверка ground-truth
Метод: Корреляция между _true_relevance и Score от алгоритма
Результат:
Component correlation with true relevance (Spearman):
  keyword_score: +0.985
  cosine_sim:    +0.915
  combined:      +0.985

Интерпретация:
- Корреляция +0.985 означает, что Score алгоритма почти полностью совпадает с ground-truth
- Это подтверждает, что алгоритм работает корректно
