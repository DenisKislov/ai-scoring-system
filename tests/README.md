# Проверки и бенчмарки

Из корня проекта, Python 3.13 (Linux/macOS; в Windows — WSL для Python-драйвера):

```bash
python -m pip install -r requirements.lock -r tests/requirements.txt
python -m pytest -q
CI=true npm test --prefix frontend -- --watchAll=false --runInBand
npm run build --prefix frontend
```

Python-тесты используют FastAPI TestClient и mongomock; рабочая MongoDB не нужна. Проверка исходного пользовательского PDF-корпуса намеренно пропускается без отдельного включения. Тесты проверяют извлечение, нормализацию, метрики, неизменность Score при смене пула, сортировку со стажем, API, HR-историю и сбои.

## Полный путь на синтетических PDF

```bash
python -m pmi verify
python -m pmi quality
python -m pmi live
```

По умолчанию результаты выводятся в консоль, файлы отчёта не создаются. Экспорт включается явно: `--output ПАПКА`. Код завершения отражает результат запущенных технических проверок.

`quality` проверяет PDF → текст → навыки и стаж → Score → рейтинг. `live` дополнительно загружает все документы через HTTP, использует настоящую MongoDB и отдельный скорер, сравнивает выдачу и сохранённые результаты. Создаётся отдельный Compose-проект на портах 18000/13000; после проверки удаляются только его ресурсы. Рабочая база не очищается.

| Средний критерий | Минимум |
|---|---:|
| NDCG@10 | 0,90 |
| Precision@5 | 0,90 |
| Precision@10 | 0,90 |
| Recall@10 | 0,15 |
| Spearman | 0,80 |

Релевантность для P/R — не менее 0,1. P/R/F1 навыков рассчитываются по категориям; отдельного минимума для них в ПМИ нет. Отчёт содержит буквальную формулу Spearman ПМИ и обычную корреляцию с поправкой на связи.

`tests/pmi/test_quality_pipeline.py` защищает от подстановки эталонного стажа и навыков в расчёт. `test_acceptance_corpus_design.py` проверяет состав, эталонную разметку и побайтовое восстановление набора. Другие генераторы и стресс-наборы проверяются отдельно. Прежний ориентир NDCG≥0,80 в `tests/eval_synthetic.py` не заменяет более строгие критерии ПМИ.

Результаты текущей поставки: [отчёт](../reports/pmi_release_2026-11-18/README.md), [методика](../docs/ACCEPTANCE_DATASET.md). Формальная приёмка остаётся отдельной процедурой; `protocol.json: accepted=false` не обязательно означает падение технических тестов.
