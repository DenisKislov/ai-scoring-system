# Руководство пользователя

1. Откройте веб-интерфейс по адресу, указанному при запуске. Счётчики показывают число вакансий и резюме в базе.
2. Создайте вакансию через форму: название, описание, навыки через запятую и критические навыки. Каждый критический навык должен быть среди требований. Либо загрузите PDF/TXT; его требования будут извлечены автоматически.
3. Выберите файлы резюме. Для PDF необходим текстовый слой; скан не распознаётся. Ошибка отдельного файла не останавливает остальные загрузки. REST API также поддерживает пакет из 1—200 файлов.
4. Выберите вакансию и отметьте критические навыки. Нажмите «Рассчитать скоринг». Выбранные критические требования сохранятся в вакансии. Рейтинг сортируется по Score, затем по опыту. Автоматический порог отбора, если задан, фильтрует выдачу по доле навыков; это фильтр, а не метрика точности.
5. Откройте строку кандидата. В карточке показаны Score, опыт, навыки, критические пробелы и вклад компонентов. Кнопка просмотра текста открывает оригинальный текст с подсветкой распознанных вариантов совпавших навыков.
6. Отметьте «Да» или «Нет». Последнее решение и история с датами сохраняются и загружаются при повторном открытии карточки.
7. Ссылка «Выгрузить JSON» открывает результаты выбранной вакансии. Оригинал файла можно скачать через API `/files/resumes/{id}` или `/files/vacancies/{id}`; SHA-256 находится в метаданных и заголовке ответа.
8. При удалении вакансии/резюме удаляются оригинал, относящиеся результаты и события HR. Массовое удаление требует подтверждения в интерфейсе. Для отдельных документов доступны DELETE-методы API.

## Сообщения об ошибках

- HTTP 400: пустой/повреждённый/неподдерживаемый файл, неправильная кодировка TXT, отсутствие текста в PDF, превышение лимита.
- HTTP 404: документ или результат неизвестной вакансии не найден.
- HTTP 422: некорректный JSON, пустое название, критический навык вне требований или неверные веса.
- HTTP 503: недоступна БД или отдельный сервис скоринга. Запрос можно повторить после восстановления; API продолжает работать.

В Swagger UI (`/docs` на API) доступны схемы и примеры запросов. Журнал API доступен через `/logs`. Лимиты файла: 8 МиБ, 200 страниц, миллион символов текста.
