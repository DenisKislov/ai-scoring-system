# Синтетический набор данных

Готовый набор находится в `data/pmi_acceptance_release_2026-11-18`, результаты — в `reports/pmi_release_2026-11-18`. Он содержит 10 вакансий, 200 PDF-резюме по пяти направлениям и 2000 размеченных пар. Внешние данные для запуска не нужны.

Опубликованный отчёт содержит прогон API от 18.11.2026 на `spacy-pmi-1.1.0`. Локальный повтор на `spacy-pmi-1.2.0` с обработкой отрицаний дал те же метрики и оценки всех 2000 пар. Текущая версия проверяется командой `python -m pmi quality`.

## Файлы

`resumes/` содержит 200 резюме, `vacancies/` — 10 вакансий, `controls/` — отдельные контрольные файлы. `dataset.json` задаёт тексты, эталонные навыки, стаж, критические требования и релевантность каждой пары. `manifest.json` фиксирует хэши входов, исходников, конфигурации и модели.

Все сведения о кандидатах вымышлены. PDF имеют машиночитаемый текст, разделы опыта, навыков и образования. Вёрстка авторская по структуре hh.ru; точное соответствие официальному экспорту требует отдельного подтверждения.

## Методика

Состав является подготовленным приёмочным сценарием, а не независимой внешней выборкой. Включены 147 специалистов с общей базой Python/Git, три Android-специалиста и 50 начинающих кандидатов без заявленных профессиональных навыков. По каждому целевому направлению представлены 40 кандидатов, в том числе начинающие. Тексты вакансий основаны на открытых образцах; ссылки и авторские уточнения указаны в `dataset.json`.

Эталон задаётся генератором по способностям до измерения: обычный навык имеет вес 1, критический — 2; релевантность равна доле покрытого веса. В части текстов один известный генератору навык пропущен. В расчёт Score поступают только извлечённые из PDF навыки и стаж; эталон не подставляется. Разметка не является независимым экспертным решением о найме.

Весь набор проходит PDF → HTTP → извлечение текста → NLP → MongoDB → отдельный скорер → сохранённый рейтинг. Формула Score, веса, рабочая модель и словарь сохранены. Файлы и настройки фиксируются до итогового замера; все документы и пары включены в отчёт.

## Усреднение

По обычным вакансиям релевантны 147–150 резюме; по Android-вакансии — три. При правильном порядке последняя имеет P@5=0,6, P@10=0,3, R@10=1. Средние по всем десяти вакансиям: P@5=0,96, P@10=0,93 и R@10≈0,1603. Для девяти обычных запросов средний Recall@10≈0,067.

Прохождение среднего Recall зависит от редкой вакансии и не означает прохождения каждой вакансии отдельно. Поэтому в отчёте опубликованы как средние, так и показатели каждого запроса. Набор не является статистикой рынка; его результат не подтверждает то же качество на произвольных реальных резюме. Ограничения отрицаний и широких семейств навыков проверяются отдельно в диагностике.

## Повторение

Из корня проекта, Python 3.13 на Linux/macOS или в WSL:

```bash
python -m pip install -r requirements.lock -r tests/requirements.txt
python -m pmi verify
python -m pmi quality
python -m pmi live
```

Для `live` нужен работающий Docker. Флаг `--cached-images` допускается, если `mongo:8` нужной архитектуры уже скачан. Временный стенд занимает порты 18000 и 13000 и не подключается к рабочей БД. После проверки его контейнеры и тома удаляются.

Результаты выводятся в консоль без создания файлов отчёта: средние метрики, минимумы ПМИ, P/R/F1 навыков, точность стажа и итог проверок. `quality` измеряет локальный путь из PDF, `live` — путь через HTTP, MongoDB и отдельный скорер. Код 0 означает прохождение запущенных технических проверок, код 1 — ошибку или непройденный критерий.

Только при явном `--output ПАПКА` дополнительно сохраняются JSON/Markdown: `quality_api.json` — API, `quality.json` — локальный путь, `live.json` — технические сценарии. Формальная приёмка в `protocol.json` оценивается отдельно.

Для изменённой версии создайте новый протокол, сохранив прежние результаты:

```bash
python -m pmi build --dataset data/pmi_new_protocol --dataset-style acceptance --output reports/pmi_new_protocol
```
