# Архитектура и NLP

Сервис сопоставляет профессиональные требования вакансии и резюме. Пользователь принимает решение о кандидате; отметки HR хранятся отдельно и не меняют алгоритм автоматически.

## Сервисы

| Сервис | Назначение |
|---|---|
| React и Nginx | Загрузка PDF/TXT, форма вакансии, рейтинг, объяснение, исходный текст и решения HR |
| FastAPI | Проверка запросов, чтение файлов, построение профилей, журнал и доступ к MongoDB |
| Scorer | Отдельный HTTP-сервис расчёта; при локальном запуске может вызываться в процессе API |
| MongoDB | Документы, оригиналы, рейтинги, история HR и параметры фильтра выдачи |

В Compose публикуются localhost-порты 3000 и 8000. Внутренние адреса: `backend:8000`, `scorer:8001`, `mongo:27017`; Nginx проксирует `/api` в backend. Данные и журнал хранятся в постоянных томах.

## Обработка документа

1. PyMuPDF извлекает текст PDF; TXT читается как UTF-8. Нужен текстовый слой, OCR не выполняется.
2. `db.builders.parse_raw_text_to_resume` формирует профиль. Должность и стаж извлекаются регулярными выражениями и правилами периодов работы.
3. `scorer.skills.extract_skills` объединяет словарные совпадения с обученной русской spaCy NER-моделью (`tok2vec` + `ner`, метка `Skill`).
4. Алиасы приводятся к каноническим именам; находки объединяются без повторов. razdel используется для токенизации, pymorphy3 — для лемматизации, встроенные правила — для сокращений и стоп-слов.
5. Извлечённые навыки и профессиональный текст поступают в скорер. Эталонная разметка бенчмарка не подставляется в рабочие признаки.

Персональные строки исключаются перед извлечением навыков и сравнением текстов. Лимиты входа: 8 МиБ, 200 страниц PDF, миллион символов текста; пакет резюме — до 200 файлов. Пустой или повреждённый документ отклоняется без остановки сервиса. Оригинальные байты сохраняются с SHA-256 и доступны через `/files/{kind}/{id}`.

## Расчёт

```text
Score = round(100 × (0.85 × keyword_score + 0.15 × cosine_sim))
```

`keyword_score` — взвешенное покрытие требований. Обычный навык весит 1, критический — 2. Сохраняются симметричные группы `skill_families.py`: инструменты одной группы могут зачесть требования друг друга. Эта эвристика может давать широкие замены и учитывается в диагностике.

`cosine_sim` — косинусная близость TF-IDF-векторов. scikit-learn обучает векторизатор на фиксированном `reference_corpus.py`; состав пула не меняет IDF и оценку одной пары. При пустом профессиональном тексте или отсутствии совпадений Score и вклады равны нулю.

Порядок выдачи: целый Score по убыванию, известный стаж по убыванию, неизвестный стаж, стабильный ID. Опыт не входит в формулу Score. В БД и HTTP-выдаче используется одинаковое упорядочивание. Сохраняются вклад компонентов, найденные и отсутствующие навыки, критические пробелы, UTC-дата, веса и fingerprint.

## Конфигурация и сохранение

`config/algorithm.json` задаёт версию `spacy-pmi-1.1.0`, веса и флаг NER. `config/skills.json` содержит расширяемые навыки и алиасы; файл перечитывается при изменении. `GET /config` показывает эффективные параметры, зависимости, хэши и доступность модели. При ошибке загрузки NER используется словарь с записью причины в журнал.

Уникальный индекс пары предотвращает дубли рейтингов. Изменение критических требований сбрасывает прежние оценки вакансии; частичный пересчёт сохраняет остальные пары только при совместимой конфигурации. Решения HR содержат последнее значение и историю событий. Удаление документа каскадно удаляет связанные записи и оригинал.

Интерфейсный фильтр использует долю покрытых требований и версионированный порог. Это отдельный механизм отображения; он не меняет Score и не является метрикой качества.
