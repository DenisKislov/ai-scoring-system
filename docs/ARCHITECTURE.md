# Архитектура и алгоритм скоринга

Сервис помогает HR сравнить профессиональные навыки резюме с требованиями выбранной вакансии. Решение о кандидате принимает пользователь; его отметки хранятся отдельно от расчёта.

## Компоненты

В Docker Compose четыре отдельных контейнера:

1. React/Nginx — форма вакансии, загрузка PDF/TXT, рейтинг, карточка, история решений и JSON.
2. FastAPI — проверка входов, извлечение текста, API/OpenAPI, журнал, работа с MongoDB.
3. Stateless scoring service — нормализация, сопоставление навыков, TF-IDF и Score. Backend обращается к нему через `SCORER_URL`; локальная разработка допускает тот же модуль в процессе API.
4. MongoDB — вакансии, резюме, оригиналы файлов, результаты, события обратной связи, конфигурация порога. Данные и журнал находятся в постоянных Docker-томах.

MongoDB и скорер доступны во внутренней сети Compose. Порты API и UI по умолчанию слушают только localhost. Адреса переопределяются через окружение; фронтенд в Docker обращается к относительному `/api`, Nginx перенаправляет его backend.

## Поток данных

PDF читается PyMuPDF, TXT — как UTF-8. Пустые, повреждённые, зашифрованные без пароля файлы, PDF без текстового слоя и неподдерживаемые форматы отклоняются с понятной ошибкой. Лимиты: 8 МиБ, 200 страниц PDF, миллион символов текста. OCR отсутствует. Оригинальные байты не преобразуются: они хранятся вместе с SHA-256, доступны через `/files/{kind}/{id}` и удаляются вместе с объектом.

`scorer.SkillExtractor` использует правила и словарь вариантов написания. Базовая онтология дополнена версионируемым `config/skills.json`. Эталонные метки оценочных CSV/JSON не используются для построения боевого словаря. Новый справочник перечитывается при изменении файла без перезапуска и изменения Python.

Опыт распознаётся по годам, месяцам, дробным формулировкам и периодам работы; пересекающиеся интервалы объединяются. При отсутствии сведений значение `null`. Отображение исходного текста и парсинг опыта отделены от расчёта Score.

## Расчёт

Из обоих текстов перед извлечением навыков и текстовым сравнением исключаются помеченные поля ФИО, возраста, пола, адреса, гражданства, контактов и другие персональные строки. Для Score не используются отдельные персональные поля БД. Опыт используется только для сортировки равных целочисленных Score.

`keyword_score` — доля покрытых требований вакансии. Обычный навык имеет вес 1, критический — 2. В версии curator-pmi-1.0.0 восстановлены исходные симметричные группы навыков куратора. Родственные технологии одной группы могут закрывать требования друг друга. Это широкая эвристика; её состав сохранён из архива. Стабильный TF-IDF, нормализация алиасов и исключение персональных строк сохранены для требований ПМИ. Отсутствующие критические навыки входят в отсутствующие требования и отдельно отмечаются в объяснении.

`cosine_sim` — косинусная близость TF-IDF-векторов нормализованных профессиональных текстов. Нормализация использует razdel, pymorphy3, стоп-слова и аббревиатуры. Один векторизатор scikit-learn обучается на фиксированном `scorer/reference_corpus.py`; пул кандидатов не меняет словарь и IDF.

`Score = round(100 × (0.85 × keyword_score + 0.15 × cosine_sim))`.

При пустом профессиональном тексте или отсутствии совпавших требований Score и вклады компонентов равны 0. Веса неотрицательны и в сумме равны 1. Вклады показаны в процентных пунктах; небольшая разница суммы и целого Score объясняется округлением. Значение всегда 0—100.

Рейтинг: Score по убыванию, при равенстве — годы опыта по убыванию, затем стабильный ID. Уникальный индекс `(vacancy_id, resume_id)` обеспечивает замену результата повторным расчётом без дублей. Вместе с результатом сохраняются компоненты, найденные/отсутствующие/критические навыки, UTC-дата, веса и fingerprint алгоритма. Изменение критических требований сбрасывает прежние оценки вакансии. Частичный пересчёт сохраняет остальные пары только при совпадении версии алгоритма, весов и критических навыков. Режим save=False не изменяет документы.

## Обратная связь и журнал

Решение HR — отдельное событие `yes/no` с UTC-датой. Повторное решение добавляет запись, а API возвращает последнее и всю историю. Эти решения не изменяют алгоритм автоматически.

В журнале есть начало/завершение загрузок и скоринга, имя/размер файла, длина текста, количество навыков, SHA-256, длительность, ошибки извлечения/БД, создание и удаление объектов. Текст резюме в структурированные события не записывается.

## Проверки и ограничения

Матрица А-1—А-20 и команды — `docs/PMI.md`. Формальная приёмка предполагает независимого испытателя, подписи комиссии, актуальные ТЗ/ПМИ и утверждённый тег. Результаты контролируемой синтетики не характеризуют качество реального найма. База старых данных может содержать неполную разметку; внешние PDF/JSON не включены в Docker-образ и требуют проверки происхождения перед использованием.
