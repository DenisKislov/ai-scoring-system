# Развёртывание и восстановление

## Docker Compose

На Linux/Windows нужны Git, Docker Engine с Compose либо Docker Desktop и браузер. Стенд ПМИ: x86-64, минимум 2 ядра, 8 ГБ RAM, 100 ГБ диска, без GPU. На Mac образы linux/amd64 запускаются в Docker Desktop; это не заменяет подтверждение характеристик приёмочного стенда.

Из корня клонированного проекта:

```bash
docker compose up --build -d --wait
```

По умолчанию UI — `http://localhost:3000`, API/Swagger — `http://localhost:8000/docs`. Четыре отдельных сервиса: frontend, backend, scorer, mongo. БД и скорер не публикуют порты наружу. Первая сборка скачивает зависимости, последующие используют кэш. Образ содержит только исходники, конфигурацию и синтетические шаблоны, без реальных PDF/JSON.

`.env.example` перечисляет настройки; копировать его в `.env` нужно только для изменения значений. Адрес API фронтенда задаётся `REACT_APP_API_URL` при сборке, адрес БД — `MONGO_URI`, адрес скорера — `SCORER_URL` (в Compose установлен автоматически). По умолчанию в демонстрации нет реальных данных. Заполнить базу можно кнопкой синтетического генератора или загрузкой PDF-набора ПМИ.

## Обновление

После получения новой утверждённой версии:

```bash
docker compose up --build -d --wait
```

Именованные тома сохраняют базу и журнал. Изменение зависимостей фиксируется в `requirements.lock`, фронтенда — в `frontend/package-lock.json`. Перед утверждением тега выполните проверки, просмотрите аудит ПДн и убедитесь, что tag указывает на commit именно проверенных исходников. Команды создания тега выполняются после согласования версии, а не на старом HEAD с незафиксированными правками.

## Восстановление после остановки

```bash
docker compose stop
docker compose up -d --wait
docker compose ps
```

Остановка не удаляет тома. `/health` проверяет доступность БД, `/status` — жив ли процесс API. После восстановления должны сохраниться числа документов, оригиналы с хэшами, результаты и история HR. Цель ПМИ — не более 30 минут; длительность фактического испытания записывается в `reports/pmi/live.json`.

Резервную копию можно получить из MongoDB штатным `mongodump --archive`, например:

```bash
docker compose exec -T mongo mongodump --archive > backup.archive
```

Восстановление из этой копии на выделенной БД: передать файл на stdin `docker compose exec -T mongo mongorestore --archive`. Восстановление не требует удаления существующей БД; при необходимой полной замене сначала согласуйте объём удаляемых данных. Резервные копии пользовательских данных хранятся вне публичного репозитория.

## Локальная разработка

Python 3.13, Node.js 22:

```bash
python -m venv .venv
python -m pip install -r requirements.lock -r tests/requirements.txt
```

Активируйте созданное окружение. Для API вне Docker установите `MONGO_URI=mongodb://localhost:27017`; для отдельного скорера — `SCORER_URL=http://localhost:8001`. Переменные задаются синтаксисом текущей оболочки. Без `SCORER_URL` API использует тот же модуль скоринга локально.

```bash
python -m uvicorn scorer.http_api:app --port 8001
python -m uvicorn api.main:app --port 8000
```

Во втором терминале фронтенд:

```bash
cd frontend
npm ci
npm start
```

## Справочник навыков

Отредактируйте `config/skills.json`: добавьте направление в `directions`; для каждого канонического навыка укажите массив алиасов. Пример:

```json
{"version":"2026-10-21","directions":{"Метрология":{"Лазерная калибровка":["лазеркалибр"]}}}
```

Добавляйте запись к существующим направлениям, сохраняя валидный JSON; код менять не требуется. Файл примонтирован в backend и scorer, оба перечитывают его при следующем извлечении. Поддерживается расширение минимум до 20 направлений. Проверка: загрузить TXT/PDF с алиасом и посмотреть канонический навык в ответе. Уже сохранённые документы автоматически не переразбираются: для них нужно повторно загрузить исходный файл.

Веса и версия алгоритма находятся в `config/algorithm.json`; сумма весов равна 1, вес критического навыка больше 1. Фиксированный референс-корпус и параметры TF-IDF описаны в `docs/ARCHITECTURE.md`. Параметры не меняются во время приёмочного прогона, кроме отдельного А-20.

## Проверки

```bash
python -m pytest -q
python -m pmi run --live
```

Фронтенд: `CI=true npm test -- --watchAll=false --runInBand` и `npm run build` в его каталоге. В PowerShell установите переменную CI отдельно. ПМИ, критерии и ручные действия — `docs/PMI.md`.
