# Развёртывание и восстановление

## Docker Compose

На Linux/Windows нужны Git, Docker Engine с Compose либо Docker Desktop и браузер. Стенд ПМИ: x86-64, минимум 2 ядра, 8 ГБ RAM, 100 ГБ диска, без GPU. На Mac образы linux/amd64 запускаются в Docker Desktop; это не заменяет подтверждение характеристик приёмочного стенда.

Из корня клонированного проекта:

```bash
docker compose up --build -d --wait
```

По умолчанию UI — `http://localhost:3000`, API/Swagger — `http://localhost:8000/docs`. Четыре отдельных сервиса: frontend, backend, scorer, mongo. БД и скорер не публикуют порты наружу. Первая сборка скачивает зависимости, последующие используют кэш. Образ содержит исходники, конфигурацию, готовую spaCy-модель, обезличенный JSON-набор `data/benchmark` и синтетические шаблоны. Исходные пользовательские PDF и обучающие тексты в образ не копируются.

`.env.example` перечисляет настройки; копировать его в `.env` нужно только для изменения значений. Адрес API фронтенда задаётся `REACT_APP_API_URL` при сборке, адрес БД — `MONGO_URI`, адрес скорера — `SCORER_URL` (в Compose установлен автоматически). По умолчанию в демонстрации нет реальных данных. Заполнить базу можно кнопкой синтетического генератора или загрузкой PDF-набора ПМИ.

## Обновление

После получения новой утверждённой версии:

```bash
docker compose up --build -d --wait
```

Именованные тома сохраняют базу и журнал. Изменение зависимостей фиксируется в `requirements.lock`, фронтенда — в `frontend/package-lock.json`. Перед утверждением тега выполните проверки, просмотрите аудит ПДн и убедитесь, что tag указывает на commit именно проверенных исходников. Команды создания тега выполняются после согласования версии, а не на старом HEAD с незафиксированными правками.

## Восстановление после остановки

```bash
docker compose stop
docker compose up -d --wait
docker compose ps
```

Остановка не удаляет тома. `/health` проверяет доступность БД, `/status` — жив ли процесс API. После восстановления должны сохраниться числа документов, оригиналы с хэшами, результаты и история HR. Цель ПМИ — не более 30 минут; длительность фактического испытания записывается в `reports/pmi/live.json`.

Резервную копию можно получить из MongoDB штатным `mongodump --archive`, например:

```bash
docker compose exec -T mongo mongodump --archive > backup.archive
```

Восстановление из этой копии на выделенной БД: передать файл на stdin `docker compose exec -T mongo mongorestore --archive`. Восстановление не требует удаления существующей БД; при необходимой полной замене сначала согласуйте объём удаляемых данных. Резервные копии пользовательских данных хранятся вне публичного репозитория.

## Локальная разработка

Python 3.13, Node.js 22:

```bash
python -m venv .venv
python -m pip install -r requirements.lock -r tests/requirements.txt
```

Активируйте созданное окружение. Для API вне Docker установите `MONGO_URI=mongodb://localhost:27017`; для отдельного скорера — `SCORER_URL=http://localhost:8001`. Переменные задаются синтаксисом текущей оболочки. Без `SCORER_URL` API использует тот же модуль скоринга локально.

```bash
python -m uvicorn scorer.http_api:app --port 8001
python -m uvicorn api.main:app --port 8000
```

Во втором терминале фронтенд:

```bash
cd frontend
npm ci
npm start
```

## Справочник навыков

Отредактируйте `config/skills.json`: добавьте направление в `directions`; для каждого канонического навыка укажите массив алиасов. Пример:

```json
{"version":"2026-10-21","directions":{"Метрология":{"Лазерная калибровка":["лазеркалибр"]}}}
```

Добавляйте запись к существующим направлениям, сохраняя валидный JSON; код менять не требуется. Файл примонтирован в backend и scorer, оба перечитывают его при следующем извлечении. Поддерживается расширение минимум до 20 направлений. Проверка: загрузить TXT/PDF с алиасом и посмотреть канонический навык в ответе. Уже сохранённые документы автоматически не переразбираются: для них используйте пересчёт сохранённого текста по инструкции ниже либо повторную загрузку.

Веса и версия алгоритма находятся в `config/algorithm.json`; сумма весов равна 1, вес критического навыка больше 1. Фиксированный референс-корпус и параметры TF-IDF описаны в `docs/ARCHITECTURE.md`. Параметры не меняются во время приёмочного прогона, кроме отдельного А-20.

## NER-навыки

Навыки документа = словарь ∪ spaCy NER-модель (`scorer/models/resume_ner`, 42 МБ, tok2vec+ner, обучена на размеченном PDF-корпусе проекта). NER включён по умолчанию (`ner_skills_enabled: true`): по повторному тесту `reports/spacy_integration_2026-11-18/` union улучшает извлечение (F1 резюме 0.544 → 0.612) и ранжирование (NDCG@10 0.682 → 0.759). Первоначальная англоязычная модель не прошла гейт (precision резюме 0.66 → 0.34) и была заменена русской — история раундов в отчёте гейта.

Управление:

- ключ `ner_skills_enabled` в `config/algorithm.json` (перечитывается при следующем извлечении навыков; переключение меняет fingerprint алгоритма в `GET /config`, и сохранённые рейтинги несравнимой конфигурации удаляются при следующем скоринге);
- env `NER_SKILLS_ENABLED` со значениями `1/true/yes` или `0/false/no` переопределяет конфиг — для экспериментов без правки файла; в Docker переменную нужно явно передать контейнеру backend и scorer;
- env `NER_SKILLS_MODEL` заменяет путь к модели (диагностика, обучение новой).

Проверка состояния: `GET /config` → поле `ner_skills` (`enabled` — эффективный флаг, `available` — выполнена реальная загрузка модели). При ошибке загрузки модель отключается до перезапуска процесса, в журнале — запись `NER-модель недоступна`, скоринг продолжается на словаре; поле `available` в `/config` покажет `false`.

Существующие документы не переразбираются автоматически: после переключения флага выполните миграцию сохранённого текста по инструкции ниже или загрузите исходники повторно. NER входит в новую версию `spacy-pmi-1.1.0`. Новые результаты, манифест и границы приёмки — `reports/spacy_integration_2026-11-18/`. Старые протоколы остаются историческими.

Переобучение модели (требует отдельного разрешения на чтение исходных PDF): `python training/ner/build_ru_dataset.py` (датасет из PDF-корпуса; каскадный матчинг, статистика покрытия и шума в `training/ner/data/ru_v1/stats.json`), затем `python training/ner/train_ner.py --lang ru --base ru_core_news_sm ...` и повторение гейта по инструкциям в `reports/ner_gate/README.md`. Перед публикацией удалите контактные строки из сериализованного словаря через `python training/ner/sanitize_model.py --model training/ner/out/ru_v1/model-best --output /tmp/resume-ner-clean`, сравните предсказания с исходной моделью и повторите проверки. После этого замените `scorer/models/resume_ner` очищенной копией. Обучающие DocBin и исходные размеченные тексты в Git не публикуются.

## Пересчёт навыков загруженных документов

Миграция обновляет `skills` и `tags` у резюме и вакансий, загруженных пользователем. Данные берутся из сохранённого текста. ID, оригиналы, решения HR и критические требования сохраняются. Импортированные наборы с эталонными навыками исключены по умолчанию. Для вакансии критические навыки сохраняются в списке требований, даже если новая модель их не нашла.

Остановите API на время применения, чтобы скоринг не записал результат по прежним навыкам. Перед миграцией сохраните резервную копию MongoDB. Скрипт уже входит в образ.

```bash
docker compose build backend scorer
docker compose stop backend
docker compose up -d --wait mongo scorer
docker compose run --rm --no-deps -T backend python scripts/backfill_skills.py --kind both --dry-run
docker compose run --rm --no-deps -T backend python scripts/backfill_skills.py --kind both
docker compose up -d --wait backend frontend
```

Скрипт удаляет прежние результаты изменённых документов перед обновлением навыков. Применение можно повторить после частичного сбоя. Конфликт параллельной правки документа отмечается в `conflicts`, процесс возвращает код 1. После миграции запустите скоринг нужных вакансий заново. `--all-sources` разрешает перезапись импортированной ручной разметки и используется только при явном намерении заменить её.

## Порог отображения

После обновления API пересчитывает устаревший порог автоматически. Параметры и версия метода доступны через `GET /threshold`. Используются извлечённые навыки и сопоставление семейств из текущего скорера. Глобальную цель определяет нижний дециль покрытия лидеров контрольного набора. В интерфейсе порог каждой выдачи ограничивается покрытием её первого кандидата. Это сохраняет top-1 в текущем списке и уменьшает влияние единичной слабой вакансии на глобальную цель. При отсутствии актуального порога отображаются все кандидаты. Принудительный пересчёт — `POST /threshold/recompute`.

## Проверки

```bash
python -m pytest -q
python -m pmi run --live
```

Фронтенд: `CI=true npm test -- --watchAll=false --runInBand` и `npm run build` в его каталоге. В PowerShell установите переменную CI отдельно. ПМИ, критерии и ручные действия — `docs/PMI.md`.

Известные особенности локальных прогонов:

- `fontTools` закреплён в `requirements.lock` и `tests/requirements.txt`; отдельная ручная установка не требуется;
- тест `test_stored_dates_keep_utc_offset_for_browser` ожидает Python 3.11+ (`datetime.fromisoformat` с суффиксом `Z`); на 3.10 он падает — используйте целевой Python 3.13.
