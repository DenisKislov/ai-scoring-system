# Испытания по ПМИ Т1-1

Реализованы сценарии А-1—А-20 из ПМИ Т1-1 v1. Автоматические проверки, реальные проверки контейнеров и действия комиссии имеют раздельные результаты. Итоговый протокол находится в `reports/pmi/protocol.md`.

## Один запуск

Из корня проекта, Python 3.13:

```bash
python -m pip install -r requirements.lock -r tests/requirements.txt
python -m pmi run --live
```

Команда создаёт синтетический PDF-набор, если его ещё нет, фиксирует входы, считает качество, измеряет производительность, проверяет исходники и историю Git, запускает pytest и отдельный Docker-стенд. Тестовые порты — 18000 и 13000. База пользователя не очищается. Тестовый проект получает случайное имя; в конце удаляются только созданные им контейнеры и тома. Флаг `--keep` оставляет этот стенд для проверки интерфейса.

Для испытаний нужны работающий Docker Desktop/Engine, доступ к официальным реестрам при первой сборке и свободные тестовые порты. В Windows команды выполняются из PowerShell; Python доступен как `python`. Виртуальное окружение активируется штатным способом.

## Отдельные этапы

```bash
python -m pmi build
python -m pmi verify
python -m pmi quality
python -m pmi performance
python -m pytest -q --junitxml=reports/pmi/unit.xml
python -m pmi audit
python -m pmi live
python -m pmi report
```

`build` создаёт `data/pmi`: 10 вакансий и 200 одностраничных PDF-резюме по шаблону кадрового документа, пять направлений, по 40 резюме на направление. Включены разработка ПО, бухгалтерия, продажи, маркетинг, проектирование. Все организации, имена и контактные поля вымышлены. Есть контрольные варианты написания навыков, критические навыки, пустые/повреждённые/неподдерживаемые PDF/TXT и две версии персональных атрибутов одного профиля.

Разметка пар вычисляется **до формирования PDF**, без вызова скорера: взвешенное покрытие скрытых навыков, критический навык весит 2, обычный — 1. В текстах есть контролируемые пропуски. Это намеренно простой приёмочный набор; более шумный реалистичный генератор шести ИТ-профилей и реальные PDF/JSON остаются отдельными диагностическими наборами. Их результаты нельзя выдавать за результаты этого протокола.

## Фиксация входов

`manifest.json` содержит SHA-256 каждого PDF, набора разметки, конфигурации, словарей и исходников алгоритма; также версии зависимостей. `quality` и `live` отказываются работать при изменении зафиксированных входов. `/config` показывает текущую версию, веса и хэши; fingerprint сохраняется с результатами скоринга.

После изменения алгоритма создайте **новый протокол**: `python -m pmi build --dataset data/pmi_v2`, затем используйте тот же `--dataset` для `quality`, `performance`, `live`. Предыдущий манифест не перезаписывается автоматически. Изменение справочника в А-20 выполняется в отдельной копии конфигурации Docker-стенда и затем отменяется.

## Метрики и критерии

Порог бинарной релевантности — 0.1. nDCG@10 использует линейный gain; минимумы: nDCG@10, Precision@5 и Precision@10 — 0.9, Recall@10 — 0.15, Spearman — 0.8. Recall усредняется только при наличии релевантных резюме. Precision/Recall/F1 извлечения навыков агрегируются по категориям с TP/FP/FN. MAP и MRR дополнительно сохраняются в JSON.

Формула (5) ПМИ записана как `1 - 6Σd² / [n(n²-1)]` и предписывает средние ранги при связях. При связях эта упрощённая формула отличается от стандартной корреляции рангов: отчёт содержит **оба значения**, приёмочный критерий использует буквальную формулу ПМИ. Это следует согласовать с ответственным за приёмку до подписания протокола.

При недостижении порогов команда возвращает ненулевой код, а отчёт содержит анализ причин. Код `run/report` остаётся ненулевым до формальной приёмки: комиссия, независимый пользователь, экспертиза ПДн и утверждение тега не автоматизируются.

## Покрытие

| Примеры | Реализация и проверки |
|---|---|
| А-1—А-2 | Форма/JSON/PDF, критические навыки, пакет до 200 файлов, неизменяемые оригиналы, SHA-256, алиасы |
| А-3—А-5 | `/config`, повторяемость, уникальный индекс результатов, сортировка по Score и опыту, вклад компонентов, карточка/подсветка/исходный текст |
| А-6—А-8 | История HR с UTC-датами, OpenAPI, выгрузка JSON, журнал событий, удаление документов и связанных результатов/истории/оригиналов |
| А-9—А-12 | `pmi quality`, все нулевые и сильные пары, критические навыки при равном числе совпадений, пулы 10/200 |
| А-13—А-15 | Отклонение файлов без падения API, HTTP 503 при остановленной MongoDB, восстановление томов и обратной связи |
| А-16 | Измерение 10×200, пакета 100, одного резюме и ранжирования 200; секунды в журнале |
| А-17—А-18 | Исключение ФИО/возраста/пола/адреса/гражданства из обоих компонентов Score; поиск контактов и секретов в исходниках и истории |
| А-19—А-20 | Четыре контейнера, инструкции запуска, изолированное расширение справочника до 20 направлений без правки Python |

А-5 и А-6 дополнены React-тестами. Модульные проверки ошибок БД не заменяют `pmi live`. Поиск регулярными выражениями не доказывает отсутствие всех ПДн; совпадения не публикуются в отчёте целиком.

## Ручной лист приёмки

В копии `docs/PMI_MANUAL.md` представитель Заказчика указывает стенд и браузеры, выполняет А-19 без помощи разработчика, проверяет внешний вид А-4/А-5, подтверждает происхождение демонстрационных данных и комплект документов. Комиссия сверяет отчёты с подписанными ТЗ/ПМИ и утверждённым тегом. Подписи, участники и реквизиты не генерируются автоматически.

## Согласованное замечание

По решению пользователя от 21.10.2026 история Git сохраняется с отмеченным контактом в старом `data/superjob_dataset.json`. Детали без публикации адреса — `reports/pmi/known_exceptions.md`. А-18 не объявляется полностью пройденным; комиссия должна рассмотреть это замечание.

Итоговая презентация технической части: `docs/PMI_results.pptx`. Дополнительный анализ непройденного порога корреляции на более шумной синтетике — `reports/pmi/diagnostic_analysis.md`.

При клонировании репозитория отсутствующие PDF восстанавливаются автоматически из фиксированного генератора. Каждый восстановленный файл сначала сравнивается с исходным SHA-256 из манифеста; расхождение останавливает запуск. Существующие изменённые файлы автоматически не заменяются. Проверка восстановления из чистой копии: `reports/pmi/regeneration_check.json`.
