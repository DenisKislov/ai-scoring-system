# Новый синтетический прогон от 18.11.2026

Набор `data/pmi_hh_2026-11-18_cached` содержит 10 вакансий, 200 PDF-резюме по пяти направлениям и 2000 размеченных пар. Это отдельный контролируемый эксперимент. Он не заменяет исходные JSON SuperJob и прежние подписанные документы.

## Что проверяется

PDF → извлечение текста → извлечение навыков и стажа → неизменный Score → рейтинг. В Docker дополнительно проверяются загрузка через API, сохранение в MongoDB, отдельный сервис скоринга и порядок сохранённой выдачи.

Эталонные навыки и стаж не передаются в расчёт. Критические требования задаются как выбор HR. Стаж используется только при равном Score. Разметка пар определяется генератором по скрытым способностям до рендеринга и измерения; часть навыков намеренно отсутствует в тексте. Это контролируемая проверка согласованности, а не независимая экспертная оценка пригодности кандидатов.

## Запуск

Из корня проекта, Python 3.13, окружение с зависимостями из `requirements.lock` и `tests/requirements.txt`. Для `live` нужен запущенный Docker.

```bash
python -m pmi build --dataset data/pmi_hh_2026-11-18_cached --dataset-style hh --output reports/pmi_hh_2026-11-18
python -m pmi verify --dataset data/pmi_hh_2026-11-18_cached
python -m pmi quality --dataset data/pmi_hh_2026-11-18_cached --output reports/pmi_hh_2026-11-18/reproduction
python -m pmi live --dataset data/pmi_hh_2026-11-18_cached --output reports/pmi_hh_2026-11-18/reproduction
```

Первая команда восстанавливает отсутствующие PDF только при точном совпадении с зафиксированными хэшами. Если все файлы уже есть, команда сообщит, что набор заморожен; переходите к `verify`. Переизмерение пишется в `reproduction`, исходный протокол сохраняется. Команда `live` создаёт отдельный Compose-проект и автоматически удаляет только его контейнеры и тома; основная база проекта не используется. Порты временного стенда: 18000 и 13000.

`live` возвращает ненулевой код, пока не оформлены все формальные свидетельства ПМИ, даже если технические испытания прошли. Проверяйте `live.json` и `quality_api.json`; поле `accepted` в `protocol.json` относится к полной приёмке, а не только к численным метрикам.

Первый Docker-прогон остановился на тайм-ауте обращения к реестру MongoDB. Повторный прогон использовал уже скачанный образ с флагом `--cached-images`; он требует, чтобы `mongo:8` нужной архитектуры уже был на компьютере. Данные и их хэши в двух попытках идентичны, изменена только настройка загрузки образа тестового стенда. Результаты первой попытки сохранены в корне отчёта, завершённой — в `cached_run`. Для повторения именно режима без скачивания добавьте `--cached-images` к последней команде.

## Результаты и ограничения

- `reports/pmi_hh_2026-11-18/README.md` — итог и границы проверки.
- `preregistration.json` — время фиксации, seed, хэши до первого замера.
- `cached_run/quality.json` — локальный путь из PDF, категории навыков и проверка стажа.
- `cached_run/quality_api.json` — фактическая выдача API без пересортировки по эталону.
- `cached_run/live.json`, `cached_run/unit.xml` — функциональные проверки и автоматические тесты.

PDF имеют авторскую одноколоночную вёрстку с разделами, рекомендованными [hh.ru](https://hh.ru/article/kak-sostavit-rezyume). Это не файлы, экспортированные самим hh.ru. Точное соответствие экспортному шаблону и принятие набора комиссией остаются отдельным пунктом. Источники тематик вакансий записаны в `dataset.json`; тексты составлены для испытаний и не являются копиями объявлений.

Формула и веса Score, словарь и рабочая spaCy-модель не изменены. Новый набор не использовался для обучения, подбора параметров, отбора удачных документов или выбора seed по результату.
